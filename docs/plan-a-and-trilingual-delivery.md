# Plan A 登录与三语交付说明

## 顾客现在怎样注册和登录

- 登录：**用户名 + 密码**。用户名 2–40 字，允许中文、英文字母、数字及 `_ . @ + -`，不能含空格；英文字母统一存为小写，登录时不区分大小写。
- 注册：用户名、8–128 位密码、确认密码必填；微信 ID、WhatsApp、手机号码至少一项。微信 ID 优先展示，其余均可空，不强制香港手机号。
- 微信 ID：6–20 字，以英文字母开头，只含字母、数字、下划线或短横线；填写微信 ID，不是昵称。
- 手机 / WhatsApp：香港 +852、8 位手机号码（4–9 开头），或内地 +86、11 位手机号码（13–19 开头）；空格、括号和短横线会规范化。可以不输入区号，服务器按号码格式识别并补齐区号。
- 忘记密码：联系老板，提供用户名及注册联系方式，人工核实后由后台重设。不发短信，不使用微信 OAuth。
- 联系资料只校验格式，不宣称验证了所有权。分享优惠每账号只能领取同一活动一次；每人限一次还需要管理员核对截图的发布账号及联系方式。后台对相同联系方式、相同截图重复提交作提示。

## 原测试账号与订单

用户确认没有真实新用户，授权清理。已在备份上演练一次性清理：8 个测试顾客账号、2 笔测试订单及其明细、凭证、申请、测试券领取记录。保留 `jchengat` 管理员（权限、原密码哈希、登录会话不变）、85 件真实商品、分类、自取点、设置和活动配置。

清理不放进常规迁移，不会在后续部署自动重复执行。仅清理备份核实的记录 ID 和截止日期之前的测试记录，防止误删后来注册的账号。全空订单清理后订单序号重新从 01 开始；用户 ID 不重置，避免新用户重复旧身份。

旧测试顾客的会话随账号删除失效，需要重新注册。管理员会话保留。以后管理员改用户名、重设密码或停用账号时，相关顾客需重新登录；修改联系方式不改变账号身份或历史订单。地址存储键在改用户名后保留，设备上的地址不会因改名消失。

## 数据库字段

沿用前一阶段已添加的 `users.wechat_id`、`whatsapp`、`account_status`、`address_storage_key`，保留 `username` 的唯一约束及原密码哈希字段。`legacy_login_phone` 留作旧版本字段，但正式顾客登录不再使用它。

| 表 | 新字段 | 类型 / 空值规则 |
|---|---|---|
| announcements | title_zh_hk, title_en, content_zh_hk, content_en | TEXT，可 NULL |
| coupon_campaigns | title_zh_hk, title_en, details_zh_hk, details_en | TEXT，可 NULL |
| orders | contact_wechat_id, contact_whatsapp | TEXT NOT NULL DEFAULT '' |

公告 `title/content`、活动 `title/details` 仍作为简体。繁体、英文由商家自行录入，单字段为空或纯空格时回落该字段简体原文。没有自动翻译、覆盖旧内容或批量翻译任务。活动标题也增加三语字段，以免只翻译正文却留下简体标题。

新订单保存下单时的微信和 WhatsApp 联系资料快照，避免顾客只填微信却无法下单，或日后更改账号资料导致旧订单联络资料消失。电话仍沿用 `orders.phone`。后台可以单独修改这笔订单的收件人、三种联系方式、地址及备注，不会覆盖价格、收款、商品或凭证。

## 数据库命令

先备份，备份文件包含私人资料，不得提交 GitHub：

```sh
npx wrangler d1 export order-db --remote --output=/安全的本地目录/order-db-before-plan-a.sql
```

较旧数据库需先补齐用户管理字段；已经升级过会跳过已有字段：

```sh
node scripts/migrate-user-management.mjs --remote --dry-run
node scripts/migrate-user-management.mjs --remote
```

本轮新增字段采用迁移文件 `migrations/2026-10-17-account-and-content-languages.sql`，建议用可重复执行的检查脚本：

```sh
node scripts/migrate-account-content.mjs --remote --dry-run
node scripts/migrate-account-content.mjs --remote
node scripts/migrate-account-content.mjs --remote --dry-run
```

最后一次 dry-run 应为 0 个缺失字段。本地验收将 `--remote` 换成 `--persist-to=/tmp/order-system-plan-a-qa`，默认操作本地 D1。**不对线上执行 schema 初始化或示例商品 seed，不重新导入商品。**

测试数据清理属于本次单独授权的操作，不是常规升级命令，不应在正式开店后重新清空数据库。

## 三语界面覆盖

字典集中至 `src/client/i18n.js`，保留原有语言键；所有顾客组件统一调用 `t()`。本轮覆盖：

1. 首页：海报、分享入口、凑单解释、未付款提醒、公告空状态、未读数字提示。
2. 分类与商品弹层：搜索提示、搜索结果、规格选择、收藏提示、购物车按钮、固定单位标签；搜索支持当前语言的商品显示名称。
3. 购物车与结算：多人拼单解释、地址、优惠券识别/空状态/重试、实际付款币种选择、付款渠道、金额项目及提交按钮。
4. 我的与账号：用户名登录、注册联系方式、格式错误、忘记密码、账号停用/更新提示、地址管理。
5. 公告：列表标题、空状态、未读角标，以及按语言读取商家标题/正文。
6. 优惠券与分享活动：活动说明、三种社交平台上传/审核状态、每人一次规则、复制文案、关闭后返回上传指引。
7. 订单详情：待确认、付款说明、立即/稍后上传、选图和确认上传、保存凭证、退款与单独配送申请、申请处理状态、取货核对说明。
8. 联系客服、售后、配送规则、科大福利、新手指引及启动失败提示。

后台管理界面本身继续使用中文；公告和优惠券编辑器提供简体、繁体、English 三套商家内容输入框。既有商品名称、规格、简介属于商品内容，未改数据库原文；沿用商品名显示翻译和未提供译名时的原文回落。

## 验收步骤

### 顾客流程

1. 新注册一个用户名，只填微信 ID；再分别测试只填香港号码、只填内地 WhatsApp。全部联系方式留空、无效号码、无效微信 ID、短密码、密码不一致应报错。
2. 用用户名及密码登录；英文字母大小写应均可登录，手机号不作为新账号登录名。
3. 点忘记密码，看到人工找回说明、老板微信及 WhatsApp。
4. 简体、繁体、English 分别检查：首页 → 分类搜索 → 加入购物车 → 结算 → 我的 → 公告 → 优惠券 → 订单详情。界面按钮、固定说明跟随语言。商家未录入的译文应显示简体原文；这属于明确的内容回落。
5. 自取点选择科大，起送额 ¥500；普通点 ¥1000。自取运费均为 0；到家 ¥30。HKD / CNY 看价切换与付款币种独立，微信/支付宝只收 CNY，FPS 只收 HKD。
6. 下单后立即上传，以及关掉付款窗口、稍后从订单页上传，各测试一次。选图后应有可点击的确认按钮；提交后进入待确认，刷新及重新打开订单仍显示已保存凭证，后台也可查看。
7. 手机窄屏滚动结算、规则、上传、申请弹层，提交/关闭按钮均可到达；连续点击提交不能重复发送。
8. 分享活动上传截图 → 后台审核通过 → 我的优惠券到账 → 结算满 ¥15 减 ¥5；同账号同活动重复申请/发券不能增加第二张。关闭活动后有下次返回路径指引。

### 商家内容与用户管理

1. 公告简体、繁体、英文分别录入不同文字，保存后编辑应回填原文。三种顾客语言分别显示对应内容。
2. 清空繁体标题但保留繁体正文，顾客繁体页标题回落简体、正文保留繁体；英文同理。旧公告不自动生成译文。
3. 优惠券活动名称及说明做同样的语言与回落核对。
4. 发布自取点公告，顾客首页及“我的”显示未读数字提示，点开消息后已读；群消息仍由商家手工发送。
5. 用户列表核对用户名、微信、WhatsApp、电话、注册时间、订单数、累计消费、状态。打开用户查看所有订单，点订单跳转详情。
6. 修改用户资料，历史订单不变；改用户名后旧登录失效，联系资料变更不更改登录名。
7. 后台重设密码后旧密码/旧会话失效，新密码可以登录；界面只显示“已设置/未设置”，不会返回密码或哈希。
8. 停用顾客不能登录/继续下单，启用后可重新登录。不能通过该表单修改 `is_admin`、停用管理员或改掉 `jchengat` 的账号名。
9. 已确认收款的待配送自取订单申请单独配送或退款；管理员核实额外收款/线下退款后处理。发货及完成状态保持有效，凭证不会消失。

密码使用带随机盐的 PBKDF2 哈希。哈希用于验证输入密码，不能反推出原密码，因此后台只能重设，不能查看原密码。重设操作不会将新密码写入日志、审计或接口返回值。
